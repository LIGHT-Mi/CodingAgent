## Task 0：修复失败测试

输入要求 Agent：

1. 检查文件。
2. 运行测试。
3. 定位失败原因。
4. 精确修改 `calculator.py`。
5. 回读文件。
6. 再次运行测试。
7. 返回最终总结。

实际结果：

- 创建了带持久化标题的 Session 和 Task 0。
- Task 0 最终状态为 `COMPLETED`。
- 共创建 6 个 AgentStep、15 条 Message、9 个 ToolCall。
- 工具顺序包含 `list_files`、`search_files`、`read_file`、`run_command`、`edit_file`、再次 `read_file` 和再次 `run_command`。
- 第一次测试 `exit_code=1`，Runtime 没有把普通测试失败升级为 Task 失败。
- Agent 将 `return left + right` 精确修改为 `return left * right`。
- 修改后回读内容正确。
- 第二次测试 `exit_code=0`，输出 `OK`。
- Message sequence 为连续的 `0..14`，存在且仅存在一条 FINAL Message。

## Task 1：同一 Session 继续追问

在 Task 0 完成后，通过同一 Session 创建新的 Task 1，询问上一轮修改正确的原因和验证结果。

实际结果：

- Task 1 ID 与 Task 0 不同，Session ID 相同。
- Session 的 Task 列表稳定返回 Task 0、Task 1。
- Task 1 最终状态为 `COMPLETED`。
- Task 1 的最终回答能够引用上一轮的 `multiply` 错误、`left + right → left * right` 修改以及测试由失败变为通过的结论，证明历史 Prompt 和 Final Answer 已进入多轮上下文。
- Task 1 没有重新调用工具，符合“基于上一轮结论回答，不再修改文件”的要求。

本次真实回答还额外提到了 Workspace 中并不存在的 `add`、`subtract`、`divide`，这不是 ContextManager 拼装错误，但说明模型即使收到禁止虚构的 System Prompt，仍可能生成没有历史或工具证据支持的细节。多轮上下文链路验收通过，但最终回答仍需要用户审阅；当前步骤没有实现事实验证器，也不能把该限制描述成已经解决。

验收后已进一步收紧 System Prompt：历史 Assistant 最终回答只作为会话摘要，不作为新的工具证据；如果模型要补充摘要中没有明确出现的 Workspace 事实，必须重新调用工具验证。该约束用于降低无依据扩写的概率，但在没有确定性事实验证器的当前阶段，仍不承诺完全消除模型幻觉。

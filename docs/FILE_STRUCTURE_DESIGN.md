# Coding Agent 文件夹结构设计

项目采用“前后端分离 + 应用源码分层 + 工作区隔离”的文件夹结构。`backend/` 是后端工程目录，`backend/app/` 是 Python 应用源码包，前端入口、测试、文档、脚本和 agent 实际操作的工作区保留在根目录。

```text
code-agent-lab/
├── backend/
│   ├── app/
│   │   ├── api/
│   │   ├── agent/
│   │   ├── core/
│   │   ├── llm/
│   │   ├── tools/
│   │   ├── db/
│   │   └── __init__.py
│   ├── .env
│   ├── .env.example
│   ├── .python-version
│   ├── requirements.txt
│   └── alembic.ini
├── frontend/
├── workspace/
├── examples/
├── tests/
├── docs/
├── scripts/
├── README.md
└── README.txt
```

## backend/

放后端工程级内容。

主要放：

- Python 虚拟环境；
- 本地环境变量文件；
- 依赖清单；
- 数据库迁移配置；
- Python 应用源码包。

这样可以把后端工程配置和真正的应用源码区分开，后续运行 FastAPI、配置 Alembic 或管理依赖时边界更清楚。

## backend/app/

放 Python 后端应用源码。

主要放：

- API / 应用服务层；
- Agent 核心层；
- 公共配置；
- 模型适配层；
- 本地工具执行层；
- 数据库和持久化逻辑。

## backend/app/api/

放 API / 应用服务层。

主要放：

- 接收前端请求的逻辑；
- 创建任务的逻辑；
- 调用 agent 的逻辑；
- 返回执行结果的逻辑；
- 后续 Web 服务接口相关逻辑。

## backend/app/agent/

放 Agent 核心层。

主要放：

- agent 主循环；
- 对话历史管理；
- 上下文管理；
- 模型输出解析；
- 工具调用决策；
- 循环终止条件；
- 错误处理；
- 执行步骤记录。

这是整个项目最核心的部分，应保持清晰、可解释，避免由现成 agent 框架代替。

## backend/app/core/

放后端公共核心配置。

主要放：

- 环境变量读取；
- 全局配置对象；
- 密钥和连接地址配置；
- 可被多个模块共享的基础设置。

配置文件不直接写死数据库地址、模型密钥等私有信息，而是从 `.env` 或系统环境变量中读取。

## backend/app/llm/

放模型适配层。

主要放：

- 大模型 API 调用；
- 不同模型的适配逻辑；
- 模型请求格式转换；
- 模型返回结果转换；
- tool calling 相关适配。

这一层只负责和模型通信，不负责 agent 怎么执行任务。

## backend/app/tools/

放工具执行层。

主要放：

- 读文件工具；
- 写文件工具；
- 列目录工具；
- 搜索文件或文本工具；
- 执行命令工具；
- 工具参数校验；
- 工具执行结果封装。

这些工具都应该是本地自己实现的，并且要限制在允许的工作目录内执行。

## backend/app/db/

放数据库和持久化相关内容。

主要放：

- 会话记录；
- 用户任务记录；
- 模型消息记录；
- 工具调用记录；
- agent 执行步骤记录；
- 运行日志或轨迹数据。

初始版本可以使用轻量持久化方案，不需要一开始就引入复杂数据库。

## frontend/

放前端交互相关内容。

主要放：

- 命令行交互；
- 后续可能扩展的网页界面；
- 用户输入任务的界面逻辑；
- agent 执行过程的展示逻辑；
- 最终结果的展示逻辑。

## workspace/

放 agent 实际操作的工作区。

主要放：

- agent 读写的项目文件；
- agent 执行命令时使用的工作目录；
- 演示任务中的待修改代码；
- 任务运行中产生的临时内容。

agent 的文件读写和命令执行应尽量限制在这里。

## examples/

放演示样例。

主要放：

- 演示视频使用的真实编程任务；
- 小型示例项目；
- 任务输入样例；
- agent 执行前后的对比材料。

## tests/

放测试。

主要放：

- agent 循环测试；
- 模型输出解析测试；
- 工具执行测试；
- 文件读写测试；
- 工作区安全测试；
- 错误处理测试。

## docs/

放设计说明和项目文档。

主要放：

- 架构说明；
- agent loop 说明；
- 上下文管理说明；
- 工具调用说明；
- 面试讲解材料；
- 提交要求整理。

## scripts/

放辅助脚本。

主要放：

- 启动 demo 的脚本；
- 运行测试的脚本；
- 清理工作区的脚本；
- 准备演示环境的脚本。

## 和六层架构的对应关系

```text
前端交互层        -> frontend/
API / 应用服务层  -> backend/app/api/
Agent 核心层      -> backend/app/agent/
模型适配层        -> backend/app/llm/
工具执行层        -> backend/app/tools/
基础设施层        -> backend/app/db/ + workspace/
```

这种结构让后端工程配置、应用源码、前端入口和 agent 工作区各自独立，后续扩展 CLI、Web UI、数据库迁移或演示样例时边界更清楚。
